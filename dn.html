Manual Técnico - Robot ETL

Bienvenido a la documentación oficial del sistema Central ETL Multimandante (Propiedad de Effectiva SpA).

🎯 Objetivo del Sistema

Automatizar la extracción de miles de registros de gestiones telefónicas desde la plataforma heredada Vicidial, transformar los datos a formatos específicos requeridos por mandantes (como Hites), y depositarlos en servidores remotos SFTP evadiendo baneos de red mediante el uso de Selenium Headless con máscaras humanas.

Flujo Lógico del Robot

  1. Recibe la orden de inicio vía API desde el Frontend (Vue.js).
  2. Consulta en PostgreSQL las credenciales cifradas y los layouts (columnas dinámicas).
  3. Levanta Google Chrome invisible (identificándose como humano en Windows).
  4. Ingresa a Vicidial, sortea el login, navega al exportador y descarga el reporte diario en CSV.
  5. Pasa los datos a un DataFrame de Pandas, limpia caracteres corruptos, formatea fechas y filtra por RUT.
  6. Guarda un historial virgen en la tabla gestiones (PostgreSQL) usando idempotencia (borra y reescribe el día para no duplicar).
  7. Filtra la campaña específica, arma un nuevo CSV con el layout exacto guardado, y lo inyecta por SFTP.

Arquitectura del Sistema

El sistema se levanta utilizando una orquestación pura de contenedores con docker compose.

📦 Contenedores (Services)

  • db: Imagen nativa de PostgreSQL 15 Alpine. Monta su almacenamiento en un volumen persistente para no perder datos si el servidor se apaga.
  • app: Imagen personalizada basada en Python 3.11. Contiene Flask (API Backend), Pandas, SQLAlchemy y los binarios nativos de Chromium y ChromeDriver para el scraping. Corre en el puerto 9090.
  • frontend: Imagen basada en Node.js 20 Alpine. Compila y expone la interfaz de usuario Vue.js/Vite en el puerto 8088.

Comandos de Mantenimiento

Todos los comandos deben ser ejecutados en la terminal de Linux, posicionado dentro de la carpeta ~/central-etl.

🚀 Encender el Sistema (Reinicio Seguro)

Usa este comando para aplicar cambios en el código o reiniciar el sistema en segundo plano.

docker compose down && docker compose up -d --build

👀 Monitorear al Robot en Vivo (Logs)

Comando vital para ver cómo el script de Python inicia sesión, limpia datos e inyecta al FTP.

docker compose logs -f app

🛑 Apagar Todo de Emergencia

Detiene y destruye los contenedores activos (No borra la Base de Datos ni el código).

docker compose down

Solución de Problemas Frecuentes

🌐 Error ERR_CONNECTION_REFUSED al abrir el Panel

Causa: Intentar entrar con 'localhost' desde otra máquina de la red, o el servidor de Vue (Vite) está bloqueando las conexiones externas por seguridad.

Solución:

  1. Asegúrate de entrar usando la IP real del servidor (Ej: http://192.168.x.x:8088). Puedes ver la IP ejecutando hostname -I en la terminal del servidor.
  2. Verifica que en el archivo frontend/package.json, el comando de inicio tenga el flag de host: "dev": "vite --host --port 8088".

❌ El robot extrae 0 filas ("No se generó reporte")

Causa: Vicidial bloqueó el acceso, la conexión a internet está caída, o las contraseñas guardadas en el panel Vue son incorrectas.

Solución:

  1. Revisa que la URL en el panel Vue termine en /index.php (Ej: https://vicieffectiva.../index.php).
  2. Ingresa a la carpeta backend/downloads/ en tu servidor y abre las fotos (ej: 1_pantalla_login.png). Allí verás exactamente qué error le mostró la página al robot.

⚠️ El servidor físico se reinició por corte de luz

Causa: Fallo eléctrico o reinicio de Windows/Linux host.

Solución: ¡No tienes que hacer nada! El archivo docker-compose.yml tiene la instrucción restart: always. Docker encenderá la base de datos, el backend y el frontend automáticamente apenas el sistema operativo cargue.

🔄 Error de ContainerConfig al usar docker-compose

Causa: Estás usando el comando antiguo con guión (docker-compose) que es incompatible con bases de datos modernas.

Solución: Utiliza siempre la sintaxis moderna con espacio: docker compose up -d --build.
